# Yijiang Diary — M1a Core skeleton

Nothing starts recording automatically. No app wiring, UI, screen capture, inference, report, or notification is included. Call the recorder explicitly on one serial execution context; sources, aggregator, and recorder are not concurrent services. The store serializes its operations.

## Data flow

`DiaryActivitySource` → `DiaryRecorder` → exclusion and masking → wall-clock aggregation → AES-GCM SQLite store → frame cleanup.

- `AXDiaryActivitySource` only checks existing Accessibility trust, never requests it. It reads frontmost app, focused window title, and focused element value. Secure Event Input and secure AX text fields suppress text. Private-window title detection is best-effort, not a reliable browser privacy API; browser-specific detection remains necessary before app integration. It deliberately leaves `urlHost` and keyframes absent rather than guessing a browser URL or capturing pixels.
- Samples normalize `urlHost` on construction and decoding, discarding credentials, port, path, query, and fragment. The recorder masks titles, app names, and focused text with the existing `SensitivePatternMatcher`, merging overlapping matches before replacement; text is capped at 2,000 characters after masking. The matcher is pattern-based, not a universal secret detector.
- Windows are half-open Unix-epoch-aligned intervals (default 600 seconds), independent of timezone/DST. Each observation owns dwell until the next observation or explicit finish time. Excluded samples and `recordUnavailable` end attribution. `recordNext` returning false means no sample/end of replay; a live polling caller must call `recordUnavailable` on unavailable observations. No elapsed time is invented after replay EOF: call `finish(at:)` with an explicit end or an injected clock.
- Consecutive matching app/title observations with normalized 64-bit character-trigram SimHash distance ≤ 3 form a dwell run. Entries are distinct app/title pairs in first-seen order with representative text snippets. The default 60-second threshold applies to accumulated per-window entry dwell and keyframe run dwell; per-app durations include brief visits. The longest qualifying run with a frame wins; ties retain the earlier frame. Runs split at window boundaries. Empty windows are omitted; `finish` can emit a partial final window with the fixed window end. Finish ends the session.
- `DiaryStore` accepts already-sanitized skeletons. All content, including keyframe metadata, is encrypted as JSON using a 256-bit key and fresh AES-GCM nonce. Only the row ID and timestamps are clear; timestamps are also authenticated as associated data. Fetch returns windows overlapping a half-open range. Purge uses window end strictly before the cutoff. Keychain access is lazy and never used by tests.
- The private directory has mode 0700, the database 0600, an empty `.metadata_never_index`, and backup exclusion. Store errors propagate. Recorder retains failed inserts for retry before reading another sample. Successful inserts are not repeated if frame deletion fails.
- Frames must be regular files directly inside `Diary/frames`. Successful windows delete the chosen frame and other consumed frames, including deduplicated frames. Excluded frames are removed immediately. Finish removes remaining frames. No images are read or generated by production Core code. Only encrypted frame metadata remains after deletion. Failed/unprocessed frames expire by modification time (default 24 hours); retained entries expire after 7/30/90 days, or never (`nil`). Call `runCleanup` explicitly; there is no background timer.
- `DiarySettings` is a Codable value persisted only to the supplied UserDefaults instance. Defaults: disabled, 600-second windows, 60-second dwell, 30-day retention, 24-hour failed-frame TTL, report time `22:00` (metadata only). Callers explicitly construct matching policy/aggregator instances from settings; saving settings never starts recording.

Tests use isolated temporary directories, an in-memory key, injected dates, and synthetic JSON. They never invoke AX collection or the real Keychain.
